# Login 2FA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace FitStack's manual `profiles.approved` gate with a real second factor — after the password, a 6-digit code emailed via Resend must be verified before RLS will let the session touch any data.

**Architecture:** Password login creates a Supabase session as normal, but that session is inert: every user-data RLS policy calls `public.session_verified()`, which is only true once a code has been verified for that exact `session_id`. Two Deno Edge Functions hold the Resend API key and own code generation and checking; the browser never sees a code or decides whether one was correct.

**Tech Stack:** Supabase Postgres + RLS, Supabase Edge Functions (Deno), Resend (`npm:resend`), React 19 + TypeScript, Zustand, react-router-dom 7, supabase-js 2.

**Spec:** `docs/superpowers/specs/2026-08-17-login-2fa-design.md`

## Global Constraints

- **Supabase project ref:** `mdqcaqksvqkanhgjrlwa`. URL `https://mdqcaqksvqkanhgjrlwa.supabase.co`.
- **Sending domain:** `weighsfit.in`. Sender string exactly `Weighsfit <otp@weighsfit.in>`. Not `coastnow.in` — that belongs to a different project.
- **Code format:** 6 digits, generated with `crypto.getRandomValues()`. Never `Math.random()`.
- **Code storage:** bcrypt via `pgcrypto` (`extensions.crypt` / `extensions.gen_salt('bf')`). Plaintext codes are never written to the database.
- **Challenge key:** `session_id`, never `email` or `user_id` alone.
- **Expiry:** code 10 minutes. Verification 12 hours. Resend cooldown 60 seconds. Attempt limit 5.
- **Secrets:** `RESEND_API_KEY` lives only as a Supabase Edge Function secret. Never in `frontend/.env`, which Vite ships to the browser.
- **Migration numbering:** next free is `0009`. Existing migrations are applied to the remote project by hand; there is no local Supabase stack.
- **RLS style:** wrap policy subqueries as `(select public.session_verified())` to preserve the initplan caching that migration `0006` introduced.
- **No test framework exists in `frontend/`.** Verification for this feature is SQL-level (real queries), HTTP-level (real curl against deployed functions), and a scripted manual E2E pass. Do not add vitest as part of this work; do not claim a UI change is verified without running the E2E checklist in Task 7.

- [ ] **Step 1: Write the migration**

Create `supabase/migrations/0009_session_verification.sql`:

```sql
-- Replaces the manual profiles.approved gate with a real second factor.
-- A password login now yields a session that cannot read or write anything
-- until a 6-digit code, emailed via Resend, is verified FOR THAT SESSION.
-- Keying on session_id (not user_id) is what makes this second-factor rather
-- than second-screen: a login on a new device gets its own challenge.

create table public.login_challenges (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  session_id uuid not null unique,
  code_hash text not null,
  expires_at timestamptz not null,
  attempts int not null default 0,
  verified_at timestamptz,
  verified_until timestamptz,
  created_at timestamptz not null default now()
);

create index login_challenges_user_id_idx on public.login_challenges (user_id);

-- RLS on with NO policies for anon/authenticated: this table is reachable only
-- by the service role and by the security-definer functions below. A client
-- must never be able to read code_hash, even hashed.
alter table public.login_challenges enable row level security;

-- Answers "is the calling session verified?".
--
-- SECURITY DEFINER is required because an RLS policy that queries another table
-- is subject to that table's RLS, and login_challenges is closed to
-- authenticated. It sits in `public` rather than a private schema on purpose:
-- the frontend calls it over PostgREST to decide whether a restored session
-- still counts as verified.
--
-- Three properties keep that safe and MUST be preserved by any future edit:
--   1. no arguments        -> nothing to manipulate
--   2. reads only auth.jwt() -> a caller can only ask about itself
--   3. returns boolean     -> cannot leak code_hash or another user's row
create function public.session_verified() returns boolean
  language sql stable security definer set search_path = ''
as $$
  select exists (
    select 1 from public.login_challenges c
    where c.session_id = (auth.jwt() ->> 'session_id')::uuid
      and c.verified_at is not null
      and c.verified_until > now()
  );
$$;

revoke execute on function public.session_verified() from public, anon;
grant execute on function public.session_verified() to authenticated;

-- Issues (or re-issues) a challenge. Returns false if one was already issued
-- for this session less than 60 seconds ago, so the send path cannot be used
-- to bomb an inbox. Hashing happens here so the plaintext code never leaves
-- the edge function's memory.
create function public.issue_login_challenge(p_user_id uuid, p_session_id uuid, p_code text)
  returns boolean
  language plpgsql security definer set search_path = ''
as $$
begin
  if exists (
    select 1 from public.login_challenges c
    where c.session_id = p_session_id
      and c.created_at > now() - interval '60 seconds'
  ) then
    return false;
  end if;

  insert into public.login_challenges (user_id, session_id, code_hash, expires_at)
  values (
    p_user_id,
    p_session_id,
    extensions.crypt(p_code, extensions.gen_salt('bf')),
    now() + interval '10 minutes'
  )
  on conflict (session_id) do update set
    user_id        = excluded.user_id,
    code_hash      = excluded.code_hash,
    expires_at     = excluded.expires_at,
    attempts       = 0,
    verified_at    = null,
    verified_until = null,
    created_at     = now();

  return true;
end;
$$;

-- Checks a submitted code. Increments attempts on failure; a challenge is dead
-- after 5 wrong guesses, which is what stops a script from walking all 10^6
-- codes inside the 10-minute window.
create function public.consume_login_challenge(p_session_id uuid, p_code text)
  returns text
  language plpgsql security definer set search_path = ''
as $$
declare
  c public.login_challenges%rowtype;
begin
  select * into c from public.login_challenges where session_id = p_session_id;

  if not found then return 'none'; end if;
  if c.attempts >= 5 then return 'locked'; end if;
  if c.expires_at < now() then return 'expired'; end if;

  if c.code_hash <> extensions.crypt(p_code, c.code_hash) then
    update public.login_challenges set attempts = attempts + 1 where id = c.id;
    return 'invalid';
  end if;

  update public.login_challenges
    set verified_at = now(), verified_until = now() + interval '12 hours'
    where id = c.id;
  return 'ok';
end;
$$;

-- Both are service-role-only: the edge functions call them, clients never do.
revoke execute on function public.issue_login_challenge(uuid, uuid, text) from public, anon, authenticated;
revoke execute on function public.consume_login_challenge(uuid, text) from public, anon, authenticated;
grant execute on function public.issue_login_challenge(uuid, uuid, text) to service_role;
grant execute on function public.consume_login_challenge(uuid, text) to service_role;

-- ---------------------------------------------------------------------------
-- Swap the approval gate for the verification gate.
--
-- Same policy shape migration 0007 established -- only the predicate changes.
-- body_metrics and nutrition_targets stay ungated: authService.signUp writes
-- their first rows DURING signup, before verification can have happened.
-- Migration 0008 exists because re-gating them deadlocks signup. profiles also
-- stays ungated so a client can read its own row.
-- ---------------------------------------------------------------------------

alter policy "own routines" on public.routines
  using (user_id = (select auth.uid()) and (select public.session_verified()))
  with check (user_id = (select auth.uid()) and (select public.session_verified()));

alter policy "own routine exercises" on public.routine_exercises
  using (
    exists (select 1 from public.routines r where r.id = routine_id and r.user_id = (select auth.uid()))
    and (select public.session_verified())
  )
  with check (
    exists (select 1 from public.routines r where r.id = routine_id and r.user_id = (select auth.uid()))
    and (select public.session_verified())
  );

alter policy "own sessions" on public.workout_sessions
  using (user_id = (select auth.uid()) and (select public.session_verified()))
  with check (user_id = (select auth.uid()) and (select public.session_verified()));

alter policy "own sets" on public.workout_sets
  using (
    exists (select 1 from public.workout_sessions s where s.id = session_id and s.user_id = (select auth.uid()))
    and (select public.session_verified())
  )
  with check (
    exists (select 1 from public.workout_sessions s where s.id = session_id and s.user_id = (select auth.uid()))
    and (select public.session_verified())
  );

alter policy "insert own custom exercise" on public.exercises
  with check (created_by = (select auth.uid()) and is_custom = true and (select public.session_verified()));
alter policy "modify own custom exercise" on public.exercises
  using (created_by = (select auth.uid()) and (select public.session_verified()));
alter policy "delete own custom exercise" on public.exercises
  using (created_by = (select auth.uid()) and (select public.session_verified()));

alter policy "insert own custom food" on public.foods
  with check (created_by = (select auth.uid()) and is_custom = true and (select public.session_verified()));
alter policy "modify own custom food" on public.foods
  using (created_by = (select auth.uid()) and (select public.session_verified()));
alter policy "delete own custom food" on public.foods
  using (created_by = (select auth.uid()) and (select public.session_verified()));

alter policy "select own food logs" on public.food_logs
  using (user_id = (select auth.uid()) and (select public.session_verified()));
alter policy "insert own visible food logs" on public.food_logs
  with check (
    user_id = (select auth.uid())
    and exists (select 1 from public.foods f where f.id = food_id and (f.is_custom = false or f.created_by = (select auth.uid())))
    and (select public.session_verified())
  );
alter policy "modify own food logs" on public.food_logs
  using (user_id = (select auth.uid()) and (select public.session_verified()));
alter policy "delete own food logs" on public.food_logs
  using (user_id = (select auth.uid()) and (select public.session_verified()));

alter policy "own tdee estimates" on public.tdee_estimates
  using (user_id = (select auth.uid()) and (select public.session_verified()))
  with check (user_id = (select auth.uid()) and (select public.session_verified()));

alter policy "own dismissed suggestions" on public.dismissed_suggestions
  using (user_id = (select auth.uid()) and (select public.session_verified()))
  with check (user_id = (select auth.uid()) and (select public.session_verified()));

-- Verifying the code is now the approval. The manual flag goes.
alter table public.profiles drop column approved;
```

- [ ] **Step 2: Write the shared JWT reader**

Create `supabase/functions/_shared/jwt.ts`:

```ts
export interface Caller {
  userId: string
  sessionId: string
}

/**
 * Reads sub + session_id from the caller's access token.
 *
 * The signature is NOT re-verified here: Supabase Edge Functions run with
 * verify_jwt enabled by default, so a request with a bad signature never
 * reaches this code. If verify_jwt is ever turned off for these functions,
 * this becomes forgeable and must be replaced with real verification.
 */
export function readCaller(req: Request): Caller | null {
  const header = req.headers.get('Authorization')
  if (!header?.startsWith('Bearer ')) return null
  try {
    const payload = JSON.parse(atob(header.slice(7).split('.')[1]))
    if (!payload.sub || !payload.session_id) return null
    return { userId: payload.sub, sessionId: payload.session_id }
  } catch {
    return null
  }
}
```

- [ ] **Step 3: Write the function**

Create `supabase/functions/send-login-code/index.ts`:

```ts
import { createClient } from 'jsr:@supabase/supabase-js@2'
import { Resend } from 'npm:resend@4'
import { corsHeaders, json } from '../_shared/cors.ts'
import { readCaller } from '../_shared/jwt.ts'

const FROM = 'Weighsfit <otp@weighsfit.in>'

/** Cryptographically secure 6-digit code. Math.random() is predictable — never use it here. */
function generateCode(): string {
  const buf = new Uint32Array(1)
  crypto.getRandomValues(buf)
  return String(buf[0] % 1_000_000).padStart(6, '0')
}

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') return new Response('ok', { headers: corsHeaders })

  const caller = readCaller(req)
  if (!caller) return json({ error: 'unauthorized' }, 401)

  const admin = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!,
  )

  const { data: userData, error: userError } = await admin.auth.admin.getUserById(caller.userId)
  if (userError || !userData.user?.email) return json({ error: 'unauthorized' }, 401)
  const email = userData.user.email

  const code = generateCode()

  const { data: issued, error: issueError } = await admin.rpc('issue_login_challenge', {
    p_user_id: caller.userId,
    p_session_id: caller.sessionId,
    p_code: code,
  })
  if (issueError) return json({ error: 'issue_failed' }, 500)
  if (issued === false) return json({ error: 'cooldown' }, 429)

  const resend = new Resend(Deno.env.get('RESEND_API_KEY')!)
  const { error: sendError } = await resend.emails.send({
    from: FROM,
    to: email,
    subject: `${code} is your FitStack code`,
    html: `<p>Your FitStack verification code is <strong style="font-size:20px;letter-spacing:2px">${code}</strong></p>
           <p>It expires in 10 minutes. If you did not try to sign in, someone may know your password — change it.</p>`,
  })

  if (sendError) {
    // Don't strand the user with a code that was never delivered.
    await admin.from('login_challenges').delete().eq('session_id', caller.sessionId)
    return json({ error: 'send_failed' }, 502)
  }

  return json({ ok: true })
})
```

```ts
import { createClient } from 'jsr:@supabase/supabase-js@2'
import { corsHeaders, json } from '../_shared/cors.ts'
import { readCaller } from '../_shared/jwt.ts'

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') return new Response('ok', { headers: corsHeaders })

  const caller = readCaller(req)
  if (!caller) return json({ error: 'unauthorized' }, 401)

  let code: unknown
  try {
    code = (await req.json()).code
  } catch {
    return json({ error: 'invalid' }, 400)
  }
  if (typeof code !== 'string' || !/^\d{6}$/.test(code)) return json({ error: 'invalid' }, 400)

  const admin = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!,
  )

  const { data: result, error } = await admin.rpc('consume_login_challenge', {
    p_session_id: caller.sessionId,
    p_code: code,
  })
  if (error) return json({ error: 'verify_failed' }, 500)

  return result === 'ok' ? json({ ok: true }) : json({ error: result }, 400)
})
```

```ts
  async sendLoginCode(): Promise<void> {
    const { error } = await supabase.functions.invoke('send-login-code')
    if (error) {
      const body = await error.context?.json?.().catch(() => null)
      if (body?.error === 'cooldown') throw new ApiError('cooldown', 429)
      throw new ApiError('We could not send your code. Try again in a moment.', 502)
    }
  },

  /** Verifies a code, which flips this session to usable. */
  async verifyLoginCode(code: string): Promise<void> {
    const { error } = await supabase.functions.invoke('verify-login-code', { body: { code } })
    if (!error) return
    const body = await error.context?.json?.().catch(() => null)
    const messages: Record<string, string> = {
      invalid: 'That code is not right.',
      expired: 'That code expired. Send a new one.',
      locked: 'Too many wrong attempts. Log in again to start over.',
      none: 'No code is waiting. Send a new one.',
    }
    throw new ApiError(messages[body?.error] ?? 'We could not check that code.', 400)
  },

  /** Whether the restored session has already passed its second factor. */
  async isSessionVerified(): Promise<boolean> {
    const { data, error } = await supabase.rpc('session_verified')
    if (error) return false
    return data === true
```

- [ ] **Step 2: Rework `authStore.ts`**

Replace the whole of `frontend/src/stores/authStore.ts` with:

```ts
import { create } from 'zustand'
import { authService } from '@/services'
import { supabase } from '@/lib/supabase'
import type { RegisterPayload, User } from '@/types'

type AuthStatus = 'restoring' | 'authenticated' | 'pending_verification' | 'anonymous'

interface AuthState {
  status: AuthStatus
  user: User | null
  /** When a code was last sent, so the verify screen can size its cooldown. Null = none sent this page-load. */
  codeSentAt: number | null
  restore: () => Promise<void>
  register: (payload: RegisterPayload) => Promise<void>
  login: (email: string, password: string) => Promise<void>
  verify: (code: string) => Promise<void>
  resendCode: () => Promise<void>
  logout: () => Promise<void>
}

export const useAuthStore = create<AuthState>((set, get) => {
  supabase.auth.onAuthStateChange((event) => {
    if (event === 'SIGNED_OUT') set({ status: 'anonymous', user: null, codeSentAt: null })
  })

  /**
   * Sends a code without letting a mail failure break the caller.
   *
   * login() and register() must land the user on /verify even when the send
   * fails -- that screen owns the Resend button and the error display. Throwing
   * here would strand them on the login form with a pending_verification status
   * and no way to retry.
   */
  async function trySend(): Promise<void> {
    try {
      await authService.sendLoginCode()
      set({ codeSentAt: Date.now() })
    } catch {
      set({ codeSentAt: null })
    }
  }

  return {
    status: 'restoring',
    user: null,
    codeSentAt: null,

    /**
     * A restored session is only usable if its 12-hour verification window is
     * still open -- otherwise the user re-enters a code. This asks the database,
     * not local state, because the window can expire while the tab is closed.
     *
     * No code is sent here: restore() runs on every page load, and sending from
     * it would mail a code on each refresh. codeSentAt stays null and the verify
     * screen sends on mount instead.
     */
    async restore() {
      try {
        const session = await authService.restore()
        if (!session) return set({ status: 'anonymous', user: null, codeSentAt: null })
        const verified = await authService.isSessionVerified()
        set({ status: verified ? 'authenticated' : 'pending_verification', user: session.user })
      } catch {
        set({ status: 'anonymous', user: null, codeSentAt: null })
      }
    },

    /** Signup always lands on verification -- creating the account proves nothing yet. */
    async register(payload) {
      const session = await authService.signUp(payload)
      set({ status: 'pending_verification', user: session.user })
      await trySend()
    },

    /** Password is the first factor only; the session stays inert until verify(). */
    async login(email, password) {
      const session = await authService.login(email, password)
      set({ status: 'pending_verification', user: session.user })
      await trySend()
    },

    async verify(code) {
      await authService.verifyLoginCode(code)
      set({ status: 'authenticated', user: get().user, codeSentAt: null })
    },

    /** Throws on failure -- unlike trySend, the verify screen shows this one. */
    async resendCode() {
      await authService.sendLoginCode()
      set({ codeSentAt: Date.now() })
    },

    async logout() {
      await authService.logout()
      set({ status: 'anonymous', user: null, codeSentAt: null })
    },
  }
})
```

Create `frontend/src/pages/VerifyCodePage.tsx`:

```tsx
import { useEffect, useRef, useState } from 'react'
import { useNavigate } from 'react-router-dom'
import { AuthLayout } from '@/components/layout/AuthLayout'
import { Button } from '@/components/ui/Button'
import { useAuthStore } from '@/stores/authStore'
import { errorMessage } from '@/hooks/useAsync'

const COOLDOWN_SECONDS = 60

/**
 * Second factor. The session already exists at this point but RLS refuses it
 * every row until a code is verified, so this screen is the only thing the
 * user can usefully do -- there is no way to skip it by editing the URL.
 */
export function VerifyCodePage() {
  const user = useAuthStore((s) => s.user)
  const verify = useAuthStore((s) => s.verify)
  const resendCode = useAuthStore((s) => s.resendCode)
  const logout = useAuthStore((s) => s.logout)
  const codeSentAt = useAuthStore((s) => s.codeSentAt)
  const navigate = useNavigate()

  const [code, setCode] = useState('')
  const [error, setError] = useState<string | null>(null)
  const [loading, setLoading] = useState(false)
  const [cooldown, setCooldown] = useState(() =>
    codeSentAt ? Math.max(0, COOLDOWN_SECONDS - Math.floor((Date.now() - codeSentAt) / 1000)) : 0,
  )
  const inputRef = useRef<HTMLInputElement>(null)
  const sentOnMount = useRef(false)

  useEffect(() => {
    inputRef.current?.focus()
  }, [])

  /**
   * Reaching this screen without a code in flight is normal: a restored session
   * whose 12-hour window lapsed lands here directly, and restore() deliberately
   * does not send (it runs on every page load). Send once on mount in that case,
   * or the user waits on an email nobody asked for.
   *
   * The ref guards React 19 StrictMode's double-invoke in development, which
   * would otherwise fire two sends and trip the server's own 60s cooldown.
   */
  useEffect(() => {
    if (codeSentAt !== null || sentOnMount.current) return
    sentOnMount.current = true
    void resendCode()
      .then(() => setCooldown(COOLDOWN_SECONDS))
      .catch(() => setError('We could not send your code. Use Resend to try again.'))
  }, [codeSentAt, resendCode])

  useEffect(() => {
    if (cooldown <= 0) return
    const t = setTimeout(() => setCooldown((c) => c - 1), 1000)
    return () => clearTimeout(t)
  }, [cooldown])

  async function submit(e: React.FormEvent) {
    e.preventDefault()
    if (code.length !== 6) return setError('Enter all six digits.')
    setLoading(true)
    setError(null)
    try {
      await verify(code)
      navigate('/dashboard', { replace: true })
    } catch (err) {
      setError(errorMessage(err))
      setCode('')
      inputRef.current?.focus()
    } finally {
      setLoading(false)
    }
  }

  async function resend() {
    setError(null)
    try {
      await resendCode()
      setCooldown(COOLDOWN_SECONDS)
    } catch (err) {
      setError(errorMessage(err) === 'cooldown' ? 'Wait a moment before asking again.' : errorMessage(err))
    }
  }

  return (
    <AuthLayout>
      <div className="animate-scale-in rounded-2xl border border-line bg-surface p-6 text-center shadow-[var(--shadow-pop)] sm:p-7">
        <h1 className="text-xl font-bold tracking-tight text-ink">Check your email</h1>
        <p className="mt-2 text-[13.5px] leading-relaxed text-ink-muted">
          We sent a 6-digit code{user?.email ? ` to ${user.email}` : ''}. It expires in 10 minutes.
        </p>

        {error && (
          <div role="alert" className="mt-4 rounded-lg border border-danger/30 bg-danger-soft px-3 py-2.5 text-[13px] text-danger">
            {error}
          </div>
        )}

        <form onSubmit={submit} className="mt-5 flex flex-col gap-4">
          <input
            ref={inputRef}
            inputMode="numeric"
            autoComplete="one-time-code"
            maxLength={6}
            value={code}
            aria-label="6-digit verification code"
            onChange={(e) => setCode(e.target.value.replace(/\D/g, '').slice(0, 6))}
            className="w-full rounded-xl border border-line bg-surface-2 py-3 text-center text-[28px] font-semibold tracking-[0.4em] text-ink outline-none focus:border-volt"
            placeholder="000000"
          />
          <Button type="submit" size="lg" block loading={loading}>
            Verify
          </Button>
        </form>

        <button
          type="button"
          onClick={() => void resend()}
          disabled={cooldown > 0}
          className="mt-4 text-[13px] font-semibold text-volt hover:text-volt-dim disabled:text-ink-faint"
        >
          {cooldown > 0 ? `Resend code in ${cooldown}s` : 'Resend code'}
        </button>

        <div>
          <Button variant="ghost" className="mt-3" onClick={() => void logout()}>
            Log out
          </Button>
        </div>
      </div>
    </AuthLayout>
  )
}
```

## Rollback

If this needs to come out in a hurry mid-demo, the fastest safe path is to make verification vacuously true rather than reverting migrations:

```sql
create or replace function public.session_verified() returns boolean
  language sql stable security definer set search_path = ''
as $$ select true $$;
```

Every policy keeps its `user_id = auth.uid()` ownership check, so users still only see their own data — only the second factor is disabled. Restore the real body afterward.
