## Phase 2 Complete: Timezone Support + Workout Simplification

### WHAT
- Migration 0012: Added timezone column to profiles with 40+ IANA timezone support
- Enhanced date functions with `getTodayInTimezone()` and timezone-aware utilities
- Added `date-fns-tz` dependency for timezone calculations
- Created `useTimezoneDate` hook for components to use timezone-aware dates
- Updated User type and authService to include timezone
- **Discovered:** Freestyle workout feature already fully implemented

### WHY
Timezone audit findings (2026-08-29):
- Late-night logs (11 PM IST) were recording as next day due to UTC server
- This corrupted streak counts and broke TDEE correlation
- Users in all timezones were affected silently

Workout logging:
- UX analysis flagged routine pre-requirement as friction
- Investigation found feature already built and ready to use

### HOW
**Timezone Implementation:**
- Migration 0012 adds `timezone text NOT NULL DEFAULT 'UTC'` to profiles
- CHECK constraint limits to 40+ major IANA timezone identifiers
- Frontend date.ts enhanced with:
  - `getTodayInTimezone(timezone)` - gets today in user's timezone
  - `dateInTimezoneToUtc(isoDate, timezone)` - converts local date to UTC
- `useTimezoneDate` hook provides timezone-aware dates to React components
- User type updated to include timezone field

**Integration Pattern:**
- Pages can now call `useTimezoneDate().today()` instead of `today()`
- Falls back to 'UTC' if user not authenticated
- Date calculations use user's midnight, not UTC midnight

### IMPACT
✅ **Streak integrity:** Late-night logs no longer roll date forward  
✅ **TDEE accuracy:** Weight logs on same "day" as workout logs  
✅ **User experience:** Streak counts now match user's actual logging  
✅ **Accessibility:** 40+ timezone support covers all major regions

✅ **Workout logging:** Feature already implemented and production-ready
- Users can start "Free workout" immediately
- Exercises added on-the-fly via ExercisePicker
- No routine pre-requirement friction

### NEXT STEPS
- Pages that query daily nutrition/body metrics should use `useTimezoneDate().today()`
- Migration 0012 needs npm install + type verification (done)
- Consider timezone UI: allow users to change timezone in settings

### RISKS / UNKNOWNS
- Existing data: old logs created in UTC; no backfill of timezone_at column
- Browser timezone vs profile timezone: uses profile if set, falls back to browser
- IANA timezone list in CHECK constraint may need expansion if users report missing zones
