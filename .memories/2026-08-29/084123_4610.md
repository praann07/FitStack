## Phase 3 Complete: UX Friction Reduction

### WHAT
- Simplified RegisterPage: Account info only required (email, password, name)
- Body metrics & goals now optional with sensible defaults
- Enhanced NutritionTargetsPage with adaptive TDEE explanation card
- Created ErrorBoundary component to prevent blank-page crashes
- Integrated ErrorBoundary into App.tsx

### WHY
UX friction was causing signup abandonment and trust issues:
- 11-field form wall intimidated casual users
- Adaptive TDEE was a "black box" — users didn't trust it
- No error recovery — blank screens on crashes

### HOW
**Signup Simplification:**
- Only require: email, password, full_name
- Body metrics optional (defaults: 170cm, 75kg, 30yrs, moderate activity)
- Visual hints mark sections as "Optional"
- Updated form description to explain defaults

**TDEE UI Improvements:**
- New explanatory card for adaptive mode (only shows when adaptive)
- Explains: what it is, why it's better, learning timeline (7 days), confidence tracking
- Shows confidence level dynamically based on logging history
- Tip: "Keep logging for accuracy; manual overrides disable learning"

**Error Boundaries:**
- React ErrorBoundary component catches component crashes
- Shows friendly error UI instead of blank page
- "Go home" button redirects to dashboard
- Dev mode shows error details for debugging

### IMPACT
✅ **Signup friction drops:** 3 required fields vs 11  
✅ **Form completion rate improves:** Users can skip body metrics  
✅ **Trust in adaptive engine:** Clear explanation of how/why it works  
✅ **Reliability:** Crashes no longer render blank screens  
✅ **User recovery:** "Go home" button gives users escape path
